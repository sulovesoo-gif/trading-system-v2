# Trading System V2 핵심 전략

2026년 7월 확정판

## 1. 프로젝트 목표

주가가 왜 오르고 왜 내렸는지를 통계적으로 증명한다.

매매는 결과다. 우리가 찾는 것은 원인(Cause)이 가격(Result)으로 이어지는 관계다.

```text
원인
  ↓
가격
```

## 2. 절대 변하지 않는 기준

모든 분석의 기준은 고점(High)과 저점(Low)이다.

프로그램매매, 등락률, 외국인, 선물 등 어떤 데이터를 분석하더라도 추세의 시작과 끝은 고점·저점을 기준으로 판단한다.

이 원칙은 프로젝트가 실패하더라도 변경하지 않는다.

## 3. 분석 단위

분석 단위는 RAW 데이터가 아니라 추세(Trend)다.

추세는 다음 상태를 가진다.

```text
START → RISING → PEAK → FALLING → END
```

## 4. 데이터의 역할

| 데이터 | 역할 |
| --- | --- |
| 가격 | 결과(Result) |
| 프로그램 | 원인(Cause) |
| 외국인 | 원인(Cause) |
| 기관 | 원인(Cause) |
| 선물 | 원인(Cause) |

프로젝트는 원인이 가격으로 이어지는 관계를 증명한다.

## 5. Collector 원칙

Collector는 API 하나의 응답을 수집하여 RAW 데이터로 저장하는 역할만 수행한다.

- 계산하지 않는다.
- 가공하지 않는다.
- 추세를 판정하지 않는다.
- 이벤트를 탐지하지 않는다.
- 전략을 판단하지 않는다.

RAW 데이터의 Feature 변환과 Trend·Event·통계 분석은 Analysis 계층에서 수행한다.

## 6. 계층별 책임

- `collector/`
  - API 호출
  - 응답 수신
  - RAW 데이터 저장
  - 계산·가공·판단 로직을 포함하지 않는다.

- `analysis/feature/`
  - RAW 데이터를 분석 가능한 Feature로 변환한다.

- `analysis/trend/`
  - `START`, `RISING`, `PEAK`, `FALLING`, `END` 상태를 판정한다.

- `analysis/event/`
  - 프로그램 금액, 가격 변화율, 프로그램 속도, 가격 속도를 기준으로 Event를 탐지한다.

- `analysis/statistics/`
  - Pattern별 확률, 승률, 통계적 유의성 및 재현성을 검증한다.

- `strategy/`
  - 통계적으로 검증된 Pattern을 전략 조건으로 해석한다.

## 7. RAW 저장 원칙

API에서 받은 데이터는 100% 그대로 저장한다.

- 삭제하지 않는다.
- 가공하지 않는다.
- 증감 컬럼도 그대로 저장한다.

## 8. Event: 추세 전환 기준

찾아야 하는 것은 추세가 꺾이는 순간이다. 다음 네 가지 Event를 기준으로 Trend가 시작되는 순간을 찾는다.

### Event 1. Program Amount

- 10억
- 50억
- 100억

### Event 2. Price Change

고점·저점 대비 변동률을 사용한다.

- 1%
- 2%
- 3%

### Event 3. Program Velocity

- 절대속도: 현재 증가속도
- 상대속도: 직전 평균 대비 속도

### Event 4. Price Velocity

- 절대속도: 가격 상승속도
- 상대속도: 평균 대비 속도

## 9. Feature

RAW 데이터를 Feature로 변환한다.

예시는 다음과 같다.

- Program Trend
- Program Velocity
- Price Velocity
- Price Change
- Futures Trend
- Investor Trend

## 10. 가장 중요한 가설

초기 가설은 프로그램이 가격에 영향을 준다는 것이었다.

```text
프로그램
  ↓
가격
```

최근 관찰에서는 선물이 가격에 영향을 주고, 가격 변화 뒤에 프로그램이 움직이는 경우도 확인했다.

```text
선물
  ↓
가격
  ↓
프로그램
```

따라서 V2에서는 Program과 Futures를 동시에 분석한다.

## 11. SQL 검증 원칙

모든 전략은 SQL로 검증한다.

검증 예시는 다음과 같다.

- 선물 상승과 프로그램 매도가 함께 나타났을 때 주가가 상승했는가?
- 프로그램 매수와 외국인 현물 매수 뒤 다음 30분 상승 확률은 얼마인가?
- 프로그램 매도와 기관 흡수 뒤 반등 확률은 얼마인가?

## 12. Pattern Library

통계적으로 의미가 있는 경우만 Pattern으로 등록한다.

예시는 다음과 같다.

```text
P-001
프로그램 매수
  ↓
상승

P-002
선물 상승 + 프로그램 매도
  ↓
기관 흡수
  ↓
상승
```

Pattern은 승률, 통계적 유의성 및 재현성이 검증된 경우에만 전략으로 채택한다.

## 13. 최종 목표

이 프로젝트는 프로그램매매 시스템이나 수급 분석 시스템에 한정되지 않는다.

최종 목표는 가격이 움직이는 이유를 데이터로 설명하는 시스템을 만드는 것이다.

그 결과로 매수·매도 시점을 자동으로 판단하는 전략을 만든다.
