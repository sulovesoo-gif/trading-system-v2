# AI_GUIDE.md

# Trading System V2 - AI 작업 가이드

## 목적

이 문서는 ChatGPT, Codex 등 AI가 Trading System V2 프로젝트에 참여할 때 반드시 따라야 하는 공통 규칙이다.

프로젝트의 가장 중요한 원칙은 AI의 기억이 아니라 프로젝트 문서를 신뢰하는 것이다.

---

# 1. 기본 원칙

## Source of Truth

프로젝트의 공식 정보는 프로젝트 문서이다.

AI의 기억, 이전 대화, 추측보다 프로젝트 문서를 우선한다.

모순이 발생하면 반드시 사용자에게 확인한다.

---

## 추측 금지

모르는 내용을 임의로 생성하지 않는다.

다음과 같은 행동을 금지한다.

- 존재하지 않는 설계 생성
- 존재하지 않는 테이블 생성
- 존재하지 않는 컬럼 생성
- 존재하지 않는 기능 생성
- 사용자가 말하지 않은 내용을 사실처럼 작성

확실하지 않으면 질문한다.

---

## 기존 설계 존중

이미 완료된 설계를 임의로 변경하지 않는다.

구조 변경이 필요한 경우

반드시

- 변경 이유
- 영향 범위
- 장단점

을 먼저 설명하고 사용자 승인을 받는다.

---

# 2. 프로젝트 작업 범위

프로젝트 루트

D:\Project\trading-system-v2

이 프로젝트 하위에서만 작업한다.

프로젝트 외부 파일은 생성하거나 수정하지 않는다.

---

# 3. 문서 우선순위

작업 전 반드시 아래 순서대로 확인한다.

1. PROJECT_STATE.md
2. PRINCIPLES.md
3. ADR/
4. TODO.md
5. 필요한 meeting 문서

meeting 전체를 모두 읽지 않는다.

필요한 문서만 확인한다.

---

# 4. 문서 작성 규칙

모든 프로젝트 문서는 한국어로 작성한다.

Markdown 형식을 사용한다.

기술 용어는 필요 시 영문 병기를 허용한다.

예)

Smart Money(스마트머니)

---

# 5. Meeting 작성 규칙

Meeting은 회의록이다.

회의 전체를 기록하지 않는다.

다음 내용만 작성한다.

- 회의 목적
- 논의 내용
- 결정사항
- 보류사항
- TODO
- 다음 회의

긴 대화를 그대로 복사하지 않는다.

회의 내용을 요약하여 작성한다.

---

# 6. PROJECT_STATE 작성 규칙

PROJECT_STATE는 현재 프로젝트 상태만 기록한다.

회의 내용을 누적 기록하지 않는다.

항상 짧게 유지한다.

포함 내용

- 현재 목표
- 현재 단계
- 현재 진행률
- 현재 이슈
- 다음 작업

---

# 7. ADR 작성 규칙

ADR은 Architecture Decision Record이다.

다음 조건을 만족할 때만 생성한다.

- 프로젝트 전체에 영향을 주는 결정
- 장기간 유지될 결정
- 되돌리기 어려운 설계

예)

AI 기억보다 프로젝트 문서를 신뢰한다.

---

# 8. TODO 작성 규칙

현재 해야 하는 작업만 유지한다.

완료된 작업은 제거하거나 완료 처리한다.

이미 완료된 내용을 TODO에 남기지 않는다.

---

# 9. 구현 원칙

코드를 수정하기 전에

현재 구조를 먼저 이해한다.

기존 코드를 임의로 삭제하지 않는다.

리팩토링이 목적이 아니라면

구조를 변경하지 않는다.

---

# 10. 사용자 승인

다음 작업은 반드시 사용자 승인이 필요하다.

- 폴더 구조 변경
- DB 구조 변경
- API 변경
- 프로젝트 철학 변경
- 핵심 전략 변경
- 기존 기능 삭제

---

# 11. ChatGPT와 Codex 역할

ChatGPT

- 설계
- 분석
- 토론
- 회의 요약
- 문서 초안 작성

Codex

- 프로젝트 문서 반영
- 코드 구현
- 테스트
- 리팩토링
- Git 작업

---

# 12. AI 행동 원칙

항상

"현재 프로젝트 문서와 일치하는가?"

를 먼저 확인한다.

문서를 변경해야 한다면

변경 이유를 설명한다.

기존 결정을 임의로 뒤집지 않는다.

모르면 질문한다.

추측하지 않는다.

---

# 13. 최종 목표

프로젝트는 AI의 기억이 아니라 프로젝트 문서를 통해 언제든지 이어서 개발할 수 있어야 한다.

새로운 AI가 참여하더라도

PROJECT_STATE와 필요한 문서만 읽으면 프로젝트를 이어갈 수 있는 상태를 유지한다.
